# Керування по UART та OTA-лінк

> **Історичний документ.** Описаний тут ранній варіант протоколу (без префіксів)
> замінено на актуальний: `0xAA` — команди, `0x55` — OTA. Див. `HELP.md`.

## Огляд

- Прошивка переводить лінк керування/OTA з I2C-slave на UART.
- Типові піни: TX=GPIO23, RX=GPIO22, порт=UART1, швидкість=115200.
- Піни й швидкість можна перевизначити на етапі компіляції макросами:
  `APP_UART_PORT`, `APP_UART_TX_PIN`, `APP_UART_RX_PIN`, `APP_UART_BAUD`.

## Підключення

- ESP32 TX (GPIO23) → RX Master
- ESP32 RX (GPIO22) → TX Master
- Спільна земля між пристроями

## Протокол

- Байт-орієнтований, без маркера початку кадру. Команди виконуються одразу, щойно
  надходять потрібні байти.
- Записи з боку Master варто робити атомарними (одна команда = один запис), щоб
  уникнути перемішування байтів.

## Асинхронні події (пристрій → master)

- `0x90`: BT_CONNECTED
- `0x91`: BT_DISCONNECTED

## Команди (master → ESP32)

- `0x04`: NEXT_TRACK (без даних)
- `0x05`: PREV_TRACK (без даних)
- `0x03`: PLAY_PAUSE (без даних)
- `0x01`: VOL_UP (без даних)
- `0x02`: VOL_DOWN (без даних)
- `0x10`: GET_STATUS → 1 байт: `0x01` підключено, `0x00` ні
- `0x21`: LOG_AVAIL → 2 байти: `<avail_low><avail_high>`
- `0x20 <len>`: LOG_READ → до `<len>` байтів логу

## OTA (master → ESP32)

- `0xEF`: ENTER_OTA_MODE → відповідь `0xEE`
- `0xF0 <size3><size2><size1><size0>`: OTA_START (розмір big-endian) → ACK `0xAA` або `0xFF <err>`
- `0xF1 <block_hi><block_lo><len><data…>`: OTA_DATA → ACK `0xBB` або `0xFF <err>`
- `0xF2`: OTA_END → ACK `0xCC` або `0xFF <err>` (при успіху пристрій перезавантажується)
- `0xF3`: OTA_ABORT → ACK `0xDD`

## Коди помилок OTA (після 0xFF)

- `0x00`: без помилки
- `0x01`: не розпочато
- `0x02`: невірний номер блоку
- `0x03`: помилка запису
- `0x04`: помилка розділу
- `0x05`: невірна довжина
- `0x06`: зайнято

## Примітки

- Під час OTA прошивка вимикає дублювання логів у UART (тихий режим), але ACK
  продовжують передаватися.
- Для надійності надсилайте OTA_DATA помірними блоками (≤ 128 байт). Байт `<len>` —
  це розмір блоку даних.

## Приклади (hex, пробіли для читабельності)

- GET_STATUS: надіслати `10` → отримати `01` або `00`
- LOG_AVAIL: надіслати `21` → отримати `<L> <H>`
- LOG_READ(64): надіслати `20 40` → отримати до 64 байтів
- OTA_START(0x00123456): надіслати `F0 00 12 34 56` → `AA` при успіху
- OTA_DATA блок 0 з 16 байтами: `F1 00 00 10 <16 байтів>` → `BB`
- OTA_END: `F2` → `CC`, далі пристрій перезавантажується

## Якщо не працює

- Немає відповідей: перевірте підключення, швидкість 115200, що TX/RX не переплутані
  та є спільна земля.
- OTA падає на початку: перевірте живлення й наявність OTA-розділу.
- Розсинхронізація парсера (через шум на лінії): повторіть команду — парсер
  відкидає невідомі байти й синхронізується заново.
